## Overview
- **Per-post cataloging**: the user (or the web-capture pipeline) enqueues posts → in-memory analyzer queue with N slots → visual inputs read from LOCAL files (ffmpeg: 4 evenly spaced keyframes per video, ≤4 carousel slides, ≤4 page screenshots, or 1 image; all 448 px JPEG data URLs) → ONE VLM call with a strict JSON schema → `posts.ai_*` + derived `post_tags` (general/specific tiers, alias-canonicalized) and `post_entities`.
- **One local model does all LLM work**: a GGUF VLM (Qwen3-VL 4B/8B or Gemma 4 E4B/12B) served by a spawned `llama-server` handles vision cataloging, screenshot QC, chat search, query→tag suggestions, cluster naming and synonym (alias) proposals. `multilingual-e5-small` embeds tag names for clustering; whisper.cpp transcribes voice dictation. All are loopback sidecars, spawned lazily, stopped after 5 min idle.
- **Remote providers (uncommitted WIP)**: `ai-providers.ts` routes chat search, vision cataloging and QC to user-configured OpenAI-compatible endpoints (BYO key via macOS Keychain/env/Pi), with a reachability gate that parks work while a node is down. Every other AI task remains local-only.
- **Search has no vectors**: AI Search = LLM chooses tags from a deterministic, query-relevant allowlist of the user's real tags + extracts keywords → SQL ranking (IDF-weighted tags fused with field-weighted LIKE/`word_match` text relevance). Gallery "AI chips" = opt-in LLM query→tag expansion.
- **Taxonomy maintenance**: co-occurrence graph (+embedding re-weighting) clustering with LLM naming and review, LLM synonym proposals with review/canonicalization, deterministic near-duplicate merge, health stats.
- **Setup**: first-run onboarding downloads VLM + whisper + engine binaries + embedder; Settings exposes model pickers, concurrency, hardware-aware llama/whisper tuning, remote provider editor.

**What `ai-providers.ts` supports today**
- Protocol: OpenAI-compatible only — `POST {base}/v1/chat/completions` with `Authorization: Bearer`, `GET {base}/v1/models` as health probe; a trailing `/v1` in the base URL is stripped then re-appended (`ai-providers.ts:142`, `:631`). No native Anthropic Messages or Gemini API, no embeddings, no STT, no tool calls.
- Capabilities: chat (SSE + non-streaming) and vision (`image_url` data URLs) when a provider row has `vision: true`.
- Providers: `local`; `pi:<id>` auto-discovered from `~/.pi/agent` (text-only); `custom:<id>` (≤ 12) from `<userData>/ai-providers.json`. Two selections: `searchProvider` (chat search) and `visionProvider` (cataloging + QC; falls back to the search provider when it has vision).
- Keys: BYO. Secret name `SHELFY_AI_*` or `ORNITH_API_KEY` resolved from macOS Keychain, then env var; or a Pi `auth.json` key reference. The renderer only sees `secretConfigured`/`available`. Key entry from UI works on macOS only.
- Transport: Bearer only over HTTPS, loopback, or an online Tailscale peer verified via `tailscale status --json`; `redirect: 'error'`.
- Tests: `tests/electron/ai-providers.test.ts` (11 cases), `analyzer-remote.test.ts` (remote chat), `analyzer-vision-remote.test.ts` (model id + image payload, empty-stream retry, `REMOTE_UNAVAILABLE` parking).

## Background jobs, queues & concurrency
- **Analysis queue** (`analyzer.ts`): FIFO, 1–10 concurrent jobs (= llama `--parallel`), phases `pending → extracting → analyzing → done|error|cancelled`; pause/resume persisted; held while the remote route is blocked; `REMOTE_UNAVAILABLE` re-queues at front; boot `recover`; done-job pruning (200); durable mirror in `jobs`.
- **Remote calls**: global mutex — at most one remote request in flight across cataloging, QC and chat (`ai-providers.ts:405`).
- **Cluster regeneration**: one run at a time (`_clusterAbort`), groups refined serially; graph step in `worker_threads` (120 s timeout → in-process fallback).
- **Alias proposals**: one run at a time (`_aliasAbort`), batches of 40 serially.
- **Chat search**: one at a time; a new chat aborts the previous; tokens tagged with run ids.
- **Remote monitor**: `/v1/models` probe every 15 s (down) / 60 s (up).
- **Sidecar lifecycles**: llama, whisper, embedder each idle-stop after 5 min; inflight counters prevent killing busy servers.
- **Model downloads**: one per model family at a time; pause/resume via `.part` + Range.
- **Screenshot QC**: invoked by the web orchestrator with a pool of 3 (area 4).
- **Dictation**: renderer timer every 1.2 s (non-overlapping) + 100 ms audio-level timer.
- **Push throttles**: stream tokens ≤ ~12/s per job (main), renderer flush 100 ms, AI Tags aggregate reload debounced 800 ms.

### Native binaries / server-side media processing
- ffmpeg is required server-side for video keyframes (banner probe + 4 seeks), still downscale to 448 px, and QC top-square crop; inputs must live in object storage (areas 2/4). Stills can use an image-resize service; videos need an ffmpeg container unless sent natively to a video-capable provider (≈ 300 tokens/s incl. audio on Gemini-class models — pricier, but would add the audio understanding the pipeline lacks: video audio is never analyzed today).
- llama-server / whisper-server / embedder sidecars, hardware tuning, model catalogs and downloads: drop.

### Vector search requirements
- Today there are **no post vectors and no vector index**. The only vectors are tag-name embeddings (384-d e5-small, L2-normalized, cosine = dot), recomputed on every cluster regeneration and passed to a worker; never stored.
- Embeddings only re-weight EXISTING co-occurrence edges (pairs with ≥ 2 shared posts — `db.ts:4246`, `cluster-core.ts:70`); they never link tags that do not co-occur, contrary to the code comments. Dropping them (or swapping models) has limited impact; a kNN edge step is needed to get the intended synonym attraction.
- Port as-is: in-memory cosine inside a background job (O(10³–10⁴) distinct tags per user); no vector DB required.
- If semantic post search is added (net-new): ~1 vector/post (caption + description + tags + keywords), optionally 1/tag; O(10³–10⁴) per power user; must filter by user, source (web/social), media type, collection, AI status, tags AND/OR and fuse with the SQL relevance → a pgvector-style index inside the main DB is simpler than an external store. Dimensions depend on provider (384–3,072).
- Re-embedding: free today (nothing persisted). If vectors get persisted, a model change means re-embedding every row (~100–300 tokens/post) and re-tuning fusion constants (`alpha 0.5`, `minJaccard 0.15`) with `scripts/cluster-eval`.

### Redesign vs reuse
- **Reuse (pure TS)**: prompts & schemas, validators (`cleanStringArray`, `validateRefinedGroups`, `validateAliasPairs`, `intersectWithVocab`, `parseTagBlock/parseKeywordBlock`), `cluster-core.ts`, deterministic fallbacks, distinctiveness/keyword scoring logic, `analysisSummary`/ETA, most renderer views/hooks (swap IPC for HTTP/SSE).
- **Re-implement on the server DB**: `post_tags`/`post_entities`/`tag_alias`/`tag_cluster*` per user; search ranking (LIKE + `word_match` JS UDF + process-global IDF/alias/count caches → FTS/trigram indexes + per-user cached stats).
- **Redesign**: durable multi-tenant job system (quotas, fairness, pause/cancel API, provider rate limits, no global remote mutex); realtime push (SSE) instead of IPC at ~12 Hz; provider layer covering chat + vision + embeddings + STT with server-held encrypted keys (decide BYO vs managed key); dictation (streaming or single-shot STT); onboarding (provider consent, not model downloads); privacy/consent for sending users' saved media and page text to third parties.
- **Drop**: llama/whisper/embedding sidecars, `hardware.ts`, model catalogs/downloads, concurrency/tuning settings, Pi discovery, Tailscale checks, Keychain integration.
