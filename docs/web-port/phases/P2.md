## P2 lane rules

These add to EXECUTION.md's lane rules and to P1's lane rules 4–9. Rule 2 below replaces P1's rules 2 and 3.

1. **Ports and data dirs.** Task P2-k uses port `18280 + k` and `../shelfy-web-local/data/p2-<k>`.
2. **Shared registries.** Concurrent lanes may touch the files in the table below. The later lane rebases, unions the additions, takes the next free migration number (and re-freezes its schema fixture), and regenerates `openapi.json` and the TS client with the tools, never by hand. Only tasks that change the same logic are serialized.
3. **No real platform traffic.** Platform pages, API responses and CDN bytes in lanes and CI are synthetic fixtures. No lane opens instagram.com, x.com, pinterest.\* or their CDNs. Real-account runs are owner steps (P2-21–P2-25); P2-01 follows its own brief.
4. **Pacing is fixed.** IG replay: 700 ms gap, ≤100 pages per run. Scroll settle: 650 ms (IG, Pinterest), 750 ms (X). Caps: 16,000 steps and 30 min per run. Archive: 2 req/s per host group. A lane changes them only through the config defaults named here; raising them is a lead step with the owner's OK.
5. **Contracts bind both sides.** The shapes in [Contracts](#contracts) are the API between lanes that run at the same time. A lane that must change one reports it; the lead updates this file and the other lane's brief.
6. **Desktop exceptions (D25).** P2-05 may edit `electron/webview-injected.ts` and P2-16 `electron/webview-select.ts`, additively. The desktop keeps its behavior; its checks and `pnpm test:e2e` stay green.
7. **Codes need strings.** A new `ErrorCode` needs `errors.code.<code>` in EN and IT in `src/i18n/messages/errors.ts`; the web errors test fails otherwise. A new notification code needs its strings in `src/i18n/messages/activity.ts`.
8. **Extension builds and tests.** Build with `pnpm exec tsx extension/build.ts [--origin <url>]`. Unit tests are vitest in `extension/tests/`. Playwright loads `extension/dist` in Playwright's Chromium, because branded Chrome ignores `--load-extension`. The sanity check stays: no `eval`, remote code or inline scripts.
9. **Additive migrations** (§3.8 expand/contract): new tables or `ADD COLUMN` only.
10. **Secrets.** No lane prints or commits extension tokens, pairing codes or the Access service token. Tests generate their own.

## Contracts

Paths are under `/api/v1`. Fields are camelCase and times unix ms, as in the rest of the API. A lane may add fields; it may not rename or drop these without rule 5.

**C1 · Extension requests.** `Authorization: Bearer shx_…` (an `extension` token holds `ingest`, `tasks`, `uploads` and `lookup`) and `X-Shelfy-Extension: <semver>`. Below `minVersion`, or without the header, an extension-token request gets 426 `extension_outdated`, except `GET /extension/config`. While Access is on (E4), the request also carries the browser's Access cookie or the headers `CF-Access-Client-Id` and `CF-Access-Client-Secret` (P2-22).

**C2 · Pairing.**

```
POST /me/tokens/pairing-code         session, CSRF, sign-in or re-auth in the last 5 minutes
→ 201 {"code": "<43 chars>", "expiresAt": 1790899260000}      60 s, single use, SHA-256 at rest
POST /extension/pair                 public, CSRF-exempt, counted by the per-client sign-in limit
{"code": "…", "installId": "<random id>", "label": "Chrome on macOS", "version": "0.2.0"}
→ 201 {"token": "shx_…", "tokenId": "01J…", "scopes": ["ingest", "tasks", "uploads", "lookup"]}
```

**C3 · Extension config.** `GET /extension/config` (bearer `ingest`, `ETag`):

```
{"minVersion": "0.2.0",
 "platforms": {"instagram": {"passive": true, "replay": true, "scroll": true, "stopAfterKnown": 10,
                             "replayGapMs": 700, "replayMaxPages": 100, "scrollSettleMs": 650},
               "twitter":   {"passive": true, "scroll": true, "stopAfterKnown": 20, "scrollSettleMs": 750},
               "pinterest": {"passive": true, "scroll": true, "stopAfterKnown": 25, "scrollSettleMs": 650}},
 "maxSteps": 16000, "maxRunMs": 1800000, "taskPollMinutes": 5, "refreshPerSession": 200}
```

**C4 · Sync runs and sources.**

```
POST /sync-runs                      bearer ingest
{"platform": "instagram", "trigger": "manual" | "web" | "scheduled" | "passive" | "selection" | "refresh",
 "listing": {"kind": "ig_saved" | "ig_collection" | "x_bookmarks" | "pin_board", "externalId": "…" | null, "name": "…" | null},
 "collection": {"mode": "auto" | "existing" | "none", "id": 12}}
→ 201 {"id": "01J…", "incremental": true, "stopAfterKnown": 10, "collectionId": 12 | null, "resumeCursor": "…" | null}

PATCH /sync-runs/{id}                bearer ingest
{"state": "running" | "done" | "stopped" | "failed", "pages": 2, "scanned": 22,
 "stopReason": "end_of_feed" | "known_run" | "page_cap" | "time_cap" | "user" | "login_required" | "error",

→ 200 the run

GET /sync-runs?platform&state&cursor session → {"items": […], "nextCursor": …}

```

`incremental` is true when the source's last full walk reached the end of the feed (P2-G1). `resumeCursor` continues a walk that a page cap stopped (P2-G2).

**C5 · Ingest.**

```
POST /ingest/batches                 bearer ingest, Idempotency-Key: <batch ULID>, ≤ 8 MiB, ≤ 500 items
{"syncRunId": "01J…", "platform": "instagram", "source": "passive" | "replay" | "scroll" | "selection" | "refresh",
 "hasNextPage": true | false | null, "client": {"ext": "0.2.0", "parser": "<hook build id>"},
 "items": [<desktop InterceptItem: id, shortcode, postUrl, profileUrl, authorUsername, authorName, text,
            timestamp, mediaType, thumbnailUrl, media: [{type, url, videoUrl?}]>]}
→ 200 {"inserted": 12, "updated": 3, "known": 485,
       "results": [{"index": 0, "key": "ig_…", "outcome": "inserted" | "known", "changed": false}],

```

`known` counts the items already saved (`UpsertSummary.merged`), `updated` those among them that changed (P1-10 carry-over). A killed `source` answers 409 `source_disabled`.

**C10 · Archive states.** P2-02 owns the rule; P2-10 owns the breaker handoff.

| `archive_state` | Meaning | Acts on it |
|---|---|---|
| `pending`, `partial` | The server fetches what is left. | P2-10 |
| `done` | Cover and image slides stored, for the asset types the user keeps (`archiveAssetTypes`). | — |
| `client` | The extension acts: `upload_media` (URL still valid; breaker open or platform mode `client`), `refresh_media` (an IG URL expired), `hydrate_link` (an IG link post without media). **Since L17 (SPIKE-9):** hydration runs on the server first on every platform, and an IG post without media is `pending`; it becomes `client` only while IG is handed to the extension (breaker or mode), or after the server's hydration finds the post login-gated. Pinterest's default mode is `server`. | P2-14, P2-17 |
| `failed` | Gone (404, 410) or out of tries. | a new sync; P4's Jobs view retries |
| `link_only` | Metadata only, by policy: web links until capture, over quota later. | P4 |

### P2-02 · Ingest sanitizer and archive-state rule in the core — wave 1 · M

**Owns**
- New `crates/core/src/ingest/sanitize.rs`: the Rust port of `sanitizeInterceptedBatch` (`src/lib/browserSanitize.ts`) with the stricter §2.16 rules.
- New `crates/core/src/ingest/archive.rs`: the archive-state rule (C10). `crates/server/src/migrations/install.rs` and `crates/migrate/src/bundle/mod.rs` call it instead of their copies.
- `cdn_url_expiry_ms` moves out of `core::legacy::convert` into the ingest module (re-exported for the legacy reader).
- The platform host allowlists, with `PINTEREST_HOSTS` mirrored from `extension/src/hosts.ts`; a shared fixture checks both lists.
- New `scripts/golden/sanitize.ts` and `shared/golden/sanitize.jsonl`.

**Shared registries:** R5 (`ingest/mod.rs`); `scripts/golden/run.ts` (its list).

**Acceptance**
- `sanitize_batch(platform, items, now) -> SanitizedBatch { posts: Vec<IncomingPost>, rejected: Vec<Rejected { index, code }> }`.
- Rules:
  - more than 500 items → the batch is refused, not truncated;
  - an item without a usable id or canonical key → rejected (`bad_id`); a non-object → `bad_item`;
  - text ≤20,000 characters, cut on a character boundary; other strings ≤4,096;
  - URLs: http(s), ≤4,096, on the platform's allowlist (IG `www.instagram.com`, `*.cdninstagram.com`, `*.fbcdn.net`; X `x.com`, `twitter.com`, `pbs.twimg.com`, `video.twimg.com`; Pinterest `PINTEREST_HOSTS`, `*.pinimg.com`). Invalid URLs are dropped from the item, as on the desktop;
  - ≤60 media per post; the batch platform is stamped on every item.
- Mapping to `IncomingPost`:
  - keys through `ids::*` (§2.8): IG `<pk>_<owner>`, pk or shortcode → `ig_<pk>`; X rest id or status URL; Pinterest pin id or URL;
  - `text` → caption, `thumbnailUrl` → cover URL, ISO timestamp → ms (invalid → none);
  - IG/FB `oe` → `cover_url_expires_at` and `source_url_expires_at`;
  - a video slide keeps its poster in `source_url` and `videoUrl` (P2-05) in `video_url`; a direct MP4 in `url` on a video host goes to `video_url`.
- Archive-state rule (C10): inputs are the post's rows, the platform modes (`server`, `client`, `auto`) and `archiveAssetTypes` (`thumbnail` = cover or poster, `image` = image slides). The install and the bundle builder give the same states as before on their fixtures.
- Golden: the desktop function and the port agree on synthetic batches for the shared rules (ids, clamping, media filter, platform stamping). Rust-only rules have unit tests.
- proptest: arbitrary JSON never panics and the output stays bounded; deep nesting is covered.

**Assumptions**
- A key repeated in one batch is merged in order by `upsert_batch` (P1-10).

### P2-04 · Outbound HTTP client, CDN fetcher, host limits, breaker — wave 1 · L

**Owns**
- New `crates/server/src/outbound/` (`client.rs`, `resolve.rs`, `cdn.rs`, `limits.rs`, `breaker.rs`).
- `reqwest` in `Cargo.toml` and `Cargo.lock` (rustls, http2, stream; no default features).
- New `crates/server/tests/support/cdn.rs`: a fixture CDN with scripted answers.

**Shared registries:** R5, S2 (client and settings), S4 (two metrics).

**Acceptance**
- One client (§2.3): rustls, HTTP/2, ≤64 requests in flight, no cookie store, no automatic redirects. It uses `SHELFY_EGRESS_PROXY` when set (P4). A test fails if a `reqwest::Client` is built outside `outbound/`.
- Until the proxy exists (P2-G4): the resolver refuses loopback, private, link-local (incl. 169.254.169.254), CGNAT, ULA, multicast and IPv4-mapped forms. Each redirect hop (≤5) re-checks scheme, allowlist and address.
- `cdn::fetch(request) -> FetchOutcome`:
  - host groups `instagram` (`*.cdninstagram.com`, `*.fbcdn.net`), `x` (`pbs.twimg.com`, `video.twimg.com`) and `pinterest` (`*.pinimg.com`); https only;
  - browser-like `Accept` and `Accept-Language`, a desktop Chrome UA, the platform `Referer`, no credentials;
  - 30 s timeout; 15 MB cap, streamed into `UserMedia::writer(IngestLimits::ARCHIVE_IMAGE)`;
  - URL variants: X `?format=jpg&name=large`; Pinterest `/1200x/`, falling back to the served size on 403 or 404.
- Outcomes:
  - `Stored(StagedObject)`;
  - `Expired`: an `oe` in the past (no request is sent), or a 403 whose body is the expiry text;
  - `Gone`: 404, 410;
  - `Blocked`: any other 403, and 429;
  - `Transient`: 5xx, timeouts, connection errors (with `Retry-After`).
- Limits per host group: 2 req/s by default (SPIKE-2), from `SHELFY_ARCHIVE_RATE_<GROUP>`; concurrency IG 4, X 8, Pinterest 4; jitter 120–400 ms for IG and Pinterest.
- Breaker per host group: opens when ≥20 % of the last 50 outcomes, or 10 in a row, are `Blocked` (expired and gone never count); stays open 30 min, then lets one probe through. Metrics `shelfy_breaker_open{host_group}` and `shelfy_media_fetch_total{host_group,outcome}`, as the P1-16 alert rule expects.
- Test hosts reach the client only through a dev setting that the server refuses with a non-local public URL, like `SHELFY_DEV_MAILBOX`.
- Tests against the fixture CDN: every outcome; a redirect to a private address; an allowlisted name resolving to 127.0.0.1; the 15 MB cap; rate and concurrency limits with a test clock; breaker open, close and probe; an expired URL is never fetched.

**Assumptions**
- No `governor`: the limiter follows P1-15's GCRA.
- P3's provider calls and P4's video fetch use this client (cross-phase).
